# Quality Classes Overview

## Purpose

The DataQuality class hierarchy provides R6 classes for assessing data quality through domain-specific quality checks, plausibility tests, and statistical validation. These classes help identify potential data collection issues, outliers, and inconsistencies.

## Base Class: DataQuality

The `DataQuality` class is the base class that defines common quality assessment functionality. It provides:

- Statistical plausibility tests
- Outlier detection
- Missing data analysis
- Dependency rule validation
- Quality schema management
- Quality report generation
- Reference to parent Data object

**Location**: `R/class_data_quality.R`

## Relationship to Data Classes

DataQuality objects are **generated by and linked to Data objects**:

### 1. Created by Data Objects

Quality objects are created using the `generate_data_quality()` method in Data classes:

```r
# Data object generates domain-specific Quality object
data <- HouseholdData$new(data = df, uuid = "uuid")
data$standardize()

# Generate quality object
quality <- data$generate_data_quality(stage = "standardized")
```

### 2. Inherits Data Context

When a Quality object is created, it receives key information from its parent Data object:

- **`parent_data_object`**: Reference back to the Data object that created it
- **`data_hash`**: Hash of the data snapshot for version tracking
- **`variable_map`**: Variable mapping configuration from parent
- **`value_map`**: Value mapping configuration from parent
- **`data_stage_name`**: Which data stage is being assessed ("standardized" or "clean")

This inheritance ensures quality checks operate on the same data context as the parent.

### 3. Generates Quality Flags

Quality objects identify issues that feed back into the Data object's cleaning workflow:

```r
# Quality object checks data
quality <- data$generate_data_quality(stage = "standardized")
quality$run_quality_checks()

# Flags are available for review
flags <- quality$get_flagged_records()

# Data object can generate cleaning log based on quality flags
data$generate_cleaning_log(stage = "standardized")
```

### 4. Workflow Integration

Quality assessment fits into the Data workflow:

```
Data Object (standardized)
    ↓
    generates →  Quality Object
                     ↓
                 run_quality_checks()
                     ↓
                 quality flags
                     ↓
Data Object uses flags to populate cleaning_log
    ↓
Data Object applies cleaning via clean()
    ↓
Data Object (clean stage)
```

**Example:**
```r
# 1. Data object standardizes data
data <- HouseholdData$new(data = df, uuid = "uuid")
data$standardize()

# 2. Generate Quality object (linked to Data)
quality <- data$generate_data_quality(stage = "standardized")

# 3. Run quality checks
quality$run_quality_checks()
quality$export_report("quality_report.xlsx")

# 4. Review flags and generate cleaning log
data$generate_cleaning_log(stage = "standardized")

# 5. Apply cleaning
data$clean()

# 6. Optionally check quality again on cleaned data
quality_clean <- data$generate_data_quality(stage = "clean")
quality_clean$run_quality_checks()
```

See [Data Classes Overview](../Data_Classes/data_classes_overview.md) for more details on the parent-child relationship.

## Subclasses

### HealthDataQuality

Quality assessment for health services and morbidity data.

**Purpose**: Validate health survey data including illness reporting, treatment seeking, and healthcare access.

**Key Quality Checks**:
- Illness prevalence validation
- Treatment-seeking behavior patterns
- Healthcare facility coverage checks
- Symptom consistency checks
- Date consistency for illness episodes

**Location**: `R/class_data_quality_health.R`

---

### DemographicsDataQuality

Quality assessment for demographic and household data.

**Purpose**: Validate demographic indicators, household composition, and population statistics.

**Key Quality Checks**:
- Age distribution plausibility
- Gender ratio validation
- Household size consistency
- Age-sex pyramid validation
- Dependency ratio checks

**Location**: `R/class_data_quality_demographics.R`

---

### MortalityDataQuality

Quality assessment for mortality and death data.

**Purpose**: Validate death records and mortality indicators.

**Key Quality Checks**:
- Crude Death Rate (CDR) plausibility
- Under-5 Death Rate (U5DR) validation
- Death cause consistency
- Recall period validation
- Age at death distribution

**Location**: `R/class_data_quality_mortality.R`

---

### WASHDataQuality

Quality assessment for Water, Sanitation, and Hygiene (WASH) data.

**Purpose**: Validate WASH indicators including water access, sanitation facilities, and hygiene practices.

**Key Quality Checks**:
- Water source accessibility
- Sanitation facility type consistency
- Water treatment practices validation
- Handwashing facility presence
- WASH ladder classification checks

**Location**: `R/class_data_quality_wash.R`

---

### AnthropometricDataQuality

Quality assessment for anthropometric measurements.

**Purpose**: Validate anthropometric data including weight, height, MUAC, and derived z-scores.

**Key Quality Checks**:
- Measurement plausibility ranges
- Z-score flag detection (WHO standards)
- Age-measurement consistency
- Sex-specific validation
- Outlier detection for WHZ, HAZ, WAZ
- MUAC measurement validation

**Location**: `R/class_data_quality_anthropometric.R`

---

### FSLDataQuality

Quality assessment for Food Security and Livelihoods (FSL) data.

**Purpose**: Validate food security indicators including food consumption, dietary diversity, and coping strategies.

**Key Quality Checks**:
- Food Consumption Score (FCS) validation
- Household Dietary Diversity Score (HDDS) checks
- Reduced Coping Strategy Index (rCSI) validation
- Livelihood zone consistency
- Food group consumption patterns

**Location**: `R/class_data_quality_fsl.R`

---

### IYCFDataQuality

Quality assessment for Infant and Young Child Feeding (IYCF) data.

**Purpose**: Validate IYCF practices including breastfeeding, complementary feeding, and dietary diversity.

**Key Quality Checks**:
- Minimum Dietary Diversity (MDD) validation
- Minimum Meal Frequency (MMF) checks
- Breastfeeding practice consistency
- Age-appropriate feeding validation
- Food group consumption for children

**Location**: `R/class_data_quality_iycf.R`

## Common Functionality

All DataQuality classes inherit these core capabilities from the base `DataQuality` class:

### 1. Initialization

```r
quality <- HealthDataQuality$new(
  data = standardized_data_object
)
```

### 2. Quality Schema Management

```r
# Set quality schema with plausibility tests
quality$set_quality_schema(quality_schema)
```

### 3. Running Quality Checks

```r
# Run all quality checks
quality$run_quality_checks()

# Run specific checks
quality$check_outliers()
quality$check_missing_data()
quality$validate_dependencies()
```

### 4. Quality Reporting

```r
# Get quality report
report <- quality$get_quality_report()

# Get flagged records
flagged <- quality$get_flagged_records()

# Get summary statistics
summary <- quality$get_quality_summary()
```

### 5. Exporting Results

```r
# Export quality flags
quality$export_flags(file = "quality_flags.csv")

# Export full quality report
quality$export_report(file = "quality_report.xlsx")
```

## Quality Check Types

### 1. Plausibility Tests

Statistical tests to identify unlikely or impossible values:

```r
quality_schema <- list(
  plausibility = list(
    age = list(
      type = "range",
      min = 0,
      max = 120
    ),
    height_cm = list(
      type = "z_score",
      indicator = "HAZ",
      flag_threshold = 5
    )
  )
)
```

### 2. Dependency Rules

Logical consistency checks between variables:

```r
dependency_schema <- list(
  list(
    condition = "age < 12",
    expected = "school_attendance == 'no'",
    severity = "warning"
  )
)
```

### 3. Missing Data Analysis

Identify patterns of missing data:

```r
# Check missing data patterns
quality$check_missing_patterns()

# Get missing data summary
missing_summary <- quality$get_missing_summary()
```

### 4. Outlier Detection

Statistical outlier identification:

```r
# Detect outliers using IQR method
quality$detect_outliers(method = "iqr", threshold = 3)

# Detect outliers using z-score method
quality$detect_outliers(method = "zscore", threshold = 3)
```

## Usage Patterns

### Basic Workflow

```r
# 1. Standardize data first
data <- HouseholdData$new(data = df, uuid = "uuid")
data$set_variable_schema(schema)
data$standardize()

# 2. Create quality object
quality <- DemographicsDataQuality$new(data = data)

# 3. Set quality schema
quality$set_quality_schema(quality_schema)

# 4. Run quality checks
quality$run_quality_checks()

# 5. Review results
report <- quality$get_quality_report()
flagged <- quality$get_flagged_records()

# 6. Export results
quality$export_report(file = "quality_report.xlsx")
```

### Advanced Usage

```r
# Chain multiple quality assessments
demographics_quality <- DemographicsDataQuality$new(data = data)
health_quality <- HealthDataQuality$new(data = data)
wash_quality <- WASHDataQuality$new(data = data)

# Run all checks
demographics_quality$run_quality_checks()
health_quality$run_quality_checks()
wash_quality$run_quality_checks()

# Combine reports
combined_report <- rbind(
  demographics_quality$get_quality_report(),
  health_quality$get_quality_report(),
  wash_quality$get_quality_report()
)
```

## Quality Flags

Quality checks generate flags with different severity levels:

- **ERROR**: Critical issues that must be fixed (e.g., impossible values)
- **WARNING**: Suspicious values that should be reviewed (e.g., outliers)
- **INFO**: Informational messages (e.g., missing optional data)

## Key Design Principles

1. **Domain-specific**: Each subclass focuses on a specific data domain
2. **Configurable**: Quality thresholds and rules are defined in schemas
3. **Layered**: Multiple levels of checks from simple to complex
4. **Actionable**: Clear flags and messages to guide data cleaning
5. **Integrated**: Works seamlessly with Data classes for end-to-end workflows
