# Analytics Classes Overview

## Purpose

The `DataAnalytics` class hierarchy provides unified R6 classes that combine **data quality checks** and **quantitative analysis** into a single object.  Each subclass is domain-specific and inherits a default quality schema, analysis schema, and outputs schema from the base class, all of which can be customised.

## Base Class: DataAnalytics

The `DataAnalytics` class defines the shared interface for all analytics objects.  It provides:

- Quality checks via `run_quality_checks()` using `quality_schema`
- Quantitative analysis via `run_analysis()` using `analysis_schema`
- All outputs (quality + analysis) via `run_outputs()` using `outputs_schema`
- Shared `visualizations` and `tables` containers
- A `QuantDataAnalysisPlanLog` object as `data_analysis_plan`
- Survey design support for weighted analysis
- Diagnostic logs for schema validation issues

**Location**: `R/class_data_analytics.R`

## Relationship to Data Classes

`DataAnalytics` objects are **generated by Data objects** using `generate_data_analytics()`:

```r
data <- HouseholdData$new(data = df, uuid = "uuid")
data$standardize()

analytics <- data$generate_data_analytics(stage = "clean")
```

When created, the analytics object receives from its parent Data object:

- `parent_data_object` — reference back to the Data object
- `data_hash` — hash of the data snapshot for version tracking
- `variable_map` / `value_map` — mapping configuration
- `variable_label` / `value_label` — display labels
- `data_stage_name` — which stage is being analysed (`"standardized"` or `"clean"`)
- `survey_design` — srvyr survey design object (from HouseholdData)

## Workflow Integration

```
Data Object (standardized or clean)
    ↓
    generate_data_analytics()
    ↓
DataAnalytics Object
    ├── run_quality_checks()   → plausibility_results, overall_score
    ├── run_analysis()         → analysis_results
    └── run_outputs()          → visualizations, tables
```

**Complete example:**

```r
# 1. Prepare data
data <- HouseholdData$new(data = df, uuid = "uuid")
data$set_variable_schema(my_schema)
data$standardize()

# 2. Generate analytics object
analytics <- data$generate_data_analytics(stage = "clean")

# 3. Run quality checks
analytics$run_quality_checks()
cat("Overall quality score:", analytics$overall_score)

# 4. Run quantitative analysis
analytics$run_analysis()

# 5. Generate outputs (visualisations and tables)
analytics$run_outputs()

# 6. Export
analytics$export_results("analytics_output.xlsx")
```

## Subclasses

### FSLDataAnalytics

Analytics for Food Security and Livelihoods data.

**Quality checks**: FCS validation, HDDS plausibility, rCSI range checks, food group consistency.

**Analysis indicators**: FCS distribution, HDDS, rCSI, food insecurity prevalence (by category), livelihood diversity.

**Location**: `R/class_data_analytics_fsl.R`

---

### HealthDataAnalytics

Analytics for health services and morbidity data.

**Quality checks**: Illness prevalence validation, treatment-seeking patterns, date consistency for illness episodes.

**Analysis indicators**: Illness prevalence, treatment-seeking rate, healthcare facility utilisation.

**Location**: `R/class_data_analytics_health.R`

---

### DemographicsDataAnalytics

Analytics for demographic and household data.

**Quality checks**: Age distribution plausibility, gender ratio, household size consistency.

**Analysis indicators**: Population distribution, household size, dependency ratio, sex ratio, age-sex pyramid.

**Location**: `R/class_data_analytics_demographics.R`

---

### MortalityDataAnalytics

Analytics for mortality and death data.

**Quality checks**: CDR plausibility, recall period validation, age-at-death distribution.

**Analysis indicators**: Crude Death Rate (CDR), Under-5 Death Rate (U5DR), cause-specific mortality.

**Location**: `R/class_data_analytics_mortality.R`

---

### NutritionDataAnalytics

Analytics for nutrition and anthropometry data.

**Quality checks**: Measurement plausibility ranges, z-score flag detection (WHO standards), age-measurement consistency.

**Analysis indicators**: GAM/SAM prevalence, stunting, underweight, MUAC-based malnutrition, MDD, MMF.

**Location**: `R/class_data_analytics_nutrition.R`

---

### WASHDataAnalytics

Analytics for Water, Sanitation, and Hygiene data.

**Quality checks**: Water source accessibility, sanitation facility type consistency, WASH ladder classification checks.

**Analysis indicators**: Access to improved water/sanitation, handwashing, water treatment, WASH ladder.

**Location**: `R/class_data_analytics_wash.R`

---

### IYCFDataAnalytics

Analytics for Infant and Young Child Feeding data.

**Quality checks**: Breastfeeding practice consistency, MDD/MMF validation, age-appropriate feeding checks.

**Analysis indicators**: MDD, MMF, breastfeeding rates, food group consumption for children.

**Location**: `R/class_data_analytics_iycf.R`

---

### GeneralDataAnalytics

General-purpose analytics for non-sectoral indicators.

**Quality checks**: None sector-specific (empty quality schema by default).

**Analysis indicators**: Configurable non-sectoral indicators.

**Location**: `R/class_data_analytics_general.R`

---

### WaterContainerDataAnalytics

Analytics for water container testing data.

**Quality checks**: Water quality results, storage practices, E. coli results.

**Analysis indicators**: No sector-specific quantitative template (configurable via DAP).

**Location**: `R/class_data_analytics_water_container.R`

## Common Functionality

All `DataAnalytics` subclasses inherit the following from the base class:

### Running quality checks

```r
analytics$run_quality_checks()
analytics$overall_score              # Numeric quality score
analytics$plausibility_results       # Detailed results per check
analytics$quality_issues_log         # Diagnostic log from quality_diagnose()
```

### Running analysis

```r
analytics$run_analysis()
analytics$analysis_results           # Named list: survey_design and base
analytics$data_analysis_plan         # QuantDataAnalysisPlanLog object
```

### Generating outputs

```r
analytics$run_outputs()
analytics$visualizations             # List of ggplot2 objects
analytics$tables                     # List of data frames / formatted tables
```

### Diagnostic tools

```r
analytics$quality_diagnose()         # Validate quality schema
analytics$analysis_diagnose()        # Validate analysis plan
analytics$outputs_diagnose()         # Validate outputs schema
```

### Export

```r
analytics$export_results("output.xlsx")
```

## Key Design Principles

1. **Unified** — quality checks and analysis share one object, reducing boilerplate
2. **Schema-driven** — `quality_schema`, `analysis_schema`, and `outputs_schema` are all configurable
3. **Domain-specific** — each subclass ships with sensible defaults for its sector
4. **Linked to parent** — `parent_data_object` provides full traceability back to the source data
5. **Reproducible** — `data_hash` and `data_analysis_plan` (a `QuantDataAnalysisPlanLog`) support audit trails
